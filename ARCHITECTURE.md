# ARCHITECTURE.md — Automation Project

## Stack

- **Test runner:** Playwright
- **Language:** TypeScript
- **Package manager:** npm
- **Linting/formatting:** ESLint + Prettier
- **Accessibility:** axe-core (via `@axe-core/playwright`)
- **CI/CD:** GitHub Actions
- **Target UI:** Demoblaze (https://www.demoblaze.com)
- **Target API:** RESTful Booker (https://restful-booker.herokuapp.com)

## Patterns

### Page Object Model

- Each page is represented by a class in `src/pages/`.
- Page objects expose actions and assertions through typed methods.
- They do not contain test logic or assertions about business outcomes.

### Fixtures

- Shared state (authenticated page, test user, API client) is provided through Playwright fixtures.
- Fixtures live in `src/fixtures/`.

### Helpers

- Cross-cutting concerns (API client, retry logic, environment config) live in `src/helpers/`.
- Helpers are pure functions or thin wrappers without test assertions.

### Configuration

- Environment-specific values (base URLs, timeouts, credentials) are loaded from environment variables.
- `src/config/environments.ts` maps environment names to URLs.
- Playwright config reads `NODE_ENV` or defaults to `staging`.

### Reporting

- HTML report is generated by Playwright.
- Traces and screenshots are captured on failure.
- CI uploads artifacts so failures can be debugged without running locally.

## Conventions

### Naming

- Page classes: `PascalCase` + `Page` suffix (e.g., `LoginPage`).
- Spec files: `kebab-case.spec.ts`.
- Helpers/fixtures: `kebab-case.ts`.
- Selectors: prefer `data-testid` or semantic roles; fall back to accessible labels.

### Test structure

```typescript
test.describe('Feature', () => {
  test('should do something useful', async ({ page, loginPage }) => {
    // Arrange
    await loginPage.open();

    // Act
    await loginPage.login(credentials.validUser);

    // Assert
    await expect(loginPage.welcomeMessage).toBeVisible();
  });
});
```

### API tests

- Each API test creates its own data and cleans it up when possible.
- Error cases use explicit assertions on status codes and response bodies.
- The API helper wraps `fetch` or Playwright's `request` context with typed methods.

### Accessibility tests

- Each critical page is scanned with axe-core after meaningful content loads.
- WCAG 2.1 Level AA is the default ruleset.
- Findings fail the test only for violations, not best-practice suggestions.
- Keyboard navigation smoke tests complement automated scanning where needed.
